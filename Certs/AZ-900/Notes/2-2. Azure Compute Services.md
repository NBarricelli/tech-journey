# **AZ-900 Notes: Domain 2 - Azure Services**

## **Azure Compute Services**

### **Azure Virtual Machines**

- Virtual environments that can be deployed and managed quickly and easily for compute, storage, servers, etc.
- Virtualize an entire computer: OS and Hardware
- Great for applications requiring complete control of the environment
- Common use cases include testing & development, cloud app hosting, disaster recovery, and "lift and shift" migration.
- Grouped into families so you can choose a size based on workload needs.
  
![image](https://github.com/user-attachments/assets/94891652-19f7-4875-bb70-b789e0aea395)

When provisioning VMs, you choose the size (CPU cores, RAM), storage disks, and networking (IP addresses, port config, etc.). With Azure VMs, at a fundamental level, you start by selecting a family that matches your workload behavior. Then, you choose the size based on performance needs and scale as needed.

**Virtual Machine Scale Sets (VMSS)** allow you to create and manage groups of identical, load-balanced VMs. This ensures you do not have to manually keep VM config consistent and micromanage utilization. You specify the OS and quantity of VMs in the scale set, and Azure will scale them using **Auto-scale** when necessary to keep up with demand.

**Virtual Machine Availability Sets** improve VM resiliency within a region and reduce the chance that all VMs are affected by maintenance or disaster. They logically distribute VMs across:

- **Update Domain**: Groups of VMs and underlying hardware that can be restarted together during planned Azure maintenance.
- **Fault Domain** Groups of underlying hardware that share potential failure points, such as power and networking.

\
![image](https://github.com/user-attachments/assets/73faf5d3-8506-450e-9ece-9b09f2786ead)

Using the image above as an example: Each physical rack is also a Fault Domain because the resources hosted on that rack all share a power, network, or other physical failure point. Each VM, regardless of the Fault Domain or Physical Rack it is located in, is assigned to an Update Domain that it would share with another resource it can be updated/rebooted/etc with. All of this is located in one Availability Set.

### **Azure Virtual Desktop**

- A desktop and application virtualization service offered in Azure
- Allows users to securely and remotely access Windows desktop environments and apps from many different device types and locations, with the primary requirement being internet connection
- Reduces IT support overhead and can be easily distributed or revoked from specific user groups as needed

### **Azure Containers**

- Lightweight, portable environments used to package an application and its dependencies
- Containers virtualize the operating system environment rather than the underlying hardware, allowing them to use fewer resources than traditional VMs
- Can be rapidly created, stopped, restarted, and scaled -- great for applications that require those characteristics

### **Azure Functions**

- A serverless, event-driven compute service that runs code in response to triggers or events
- Allows developers to focus primarily on application code rather than provisioning and managing the underlying infrastructure
- Can automatically scale according to workload demand

### **Azure App Service**

Azure App Services is a PaaS service that can be used to build, deploy, and host web apps and APIs in the cloud.

![image](https://github.com/user-attachments/assets/b087e960-358a-4ff0-94be-b9a6be644471)

\
Each app service deployment has several front ends, which use a customized proxy-based routing module to send a request to a VM hosting the service being requested.\
These VMs run in an App Service Plan, which is a logical unit that helps with scaling web apps. All the VMs in an App Service Plan are identical and will run the same services.\
Azure Web App names have to be unique across all Azure Web Apps globally. This is because it becomes a DNS name (ex. *AzureWebApp01*.azurewebsites.net)

### **Azure Kubernetes Service**

Azure Kubernetes Service (AKS) is a managed Kubernetes service used to deploy, manage, and scale containerized applications. Azure manages much of the underlying Kubernetes infrastructure, reducing the administrative overhead of operating Kubernetes yourself.

Kubernetes itself is an open-source container orchestration platform that automates deployment, scaling, and management of containerized applications.
