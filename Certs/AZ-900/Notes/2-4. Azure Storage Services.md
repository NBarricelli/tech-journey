# **AZ-900 Notes: Domain 2 - Azure Services**

## **Azure Storage Services**

### **Azure Blob Storage**

Azure Blob Storage is designed for storing unstructured files like pictures, audio files, videos, documents, etc. These files are called **blobs**, and they are stored in containers, which can be thought of as a folder on a hard drive.

There are three types of blobs:

| Blob Type | Description | Example |
| --------- | ----------- | ------- |
| **Block blobs** | General purpose files optimized for storing large amounts of unstructured data | Pictures, videos, documents |
| **Append blobs** | Specialized for data that is continuously added to the end of a file | Log files |
| **Page blobs** | Optimized for frequent random read/write operations in virtual machines | Virtual Hard Disks (VHDs) |

#### **Blob Storage Tiers**

Azure Blob Storage is priced based on factors such as how much data you store and how frequently that data is accessed or modified. As such, Microsoft offers different storage tiers for different use cases.

| Tier Name | Use Case | Storage Cost | Access Cost | Note |
| --------- | -------- | ------------ | ----------- | ---- |
| **Hot** | Data accessed or modified frequently | Highest | Lowest | No minimum storage duration |
| **Cool** | Data accessed or modified infrequently | Lower | Higher | Recommended minimum storage duration of **30** days. Moving or deleting data earlier may result in an early deletion charge. |
| **Cold** | Data rarely accessed or modified but that still requires fast retrieval | Lower | Higher | Recommended minimum storage duration of **90** days. Moving or deleting data earlier may result in an early deletion charge. |
| **Archive** | Long-term storage for data that is rarely accessed | Lowest | Highest | Recommended minimum storage duration of **180** days. Archive is an offline tier, so data must be **rehydrated** to an online tier before it can be accessed. |

### **Azure Disk Storage**

Azure Disk Storage provides persistent, block-level storage volumes used by Azure Virtual Machines (VMs). Azure managed disks are available in several types, including HDDs and SSDs, with different performance levels for different workloads.\
*Note: When creating an Azure VM, a managed OS disk is created and attached to the VM automatically.*

### **Azure Files**

Azure Files is a managed cloud file-sharing service that provides file shares accessible using standard protocols such as **Server Message Block (SMB)** and **Network File System (NFS)**. SMB file shares can be accessed using a standard UNC path, such as `\\server\share`.

Microsoft also offers **Azure File Sync**, which allows you to sync an on-prem Windows Server with an Azure file share, providing both local access and centralized cloud storage.

### **Storage Redundancy Options**

**Locally-Redundant Storage (LRS)**: Microsoft maintains three copies of your data within a *single physical datacenter* in the primary region. This is the lowest-cost redundancy option, but it does not protect against a datacenter-wide failure.\
**Zone-Redundant Storage (ZRS)**: Microsoft maintains copies of your data synchronously across three or more Availability Zones within the primary region. This provides greater resiliency than LRS because the data remains available if an individual Availability Zone fails.

LRS and ZRS provide redundancy within the primary region. ZRS provides greater fault tolerance than LRS, but neither protects against the loss of the entire Azure region.

**Geo-Redundant Storage (GRS)**: Microsoft maintains three copies of your data using LRS within the primary region and asynchronously replicates the data to a geographically distant secondary region, where it is also stored using LRS.\
**Geo-Zone-Redundant Storage (GZRS)**: Microsoft distributes your data across three or more Availability Zones using ZRS within the primary region and asynchronously replicates the data to a geographically distant secondary region, where it is stored using LRS.

### **Storage Account Options**

- **Standard**
  - **General-purpose v2:** Recommended for most Azure Storage scenarios. Supports Blob Storage, Azure Files, Queue Storage, and Table Storage. Supports all redundancy options.

- **Premium**
  - **Block blobs:** Designed for block blobs and append blobs that require high transaction rates or consistently low latency. Supports LRS and ZRS.
  - **File shares:** Designed for high-performance Azure file shares. Supports SMB and NFS file shares and LRS and ZRS redundancy.
  - **Page blobs:** Designed for page blobs requiring high performance and low latency. Supports LRS and ZRS.

### **File Operation Methods**

**AZ-Copy**: CLI tool that can be used to copy blobs and files to and from Azure Storage. You can copy individual files and entire directories in one operation. Because it is a CLI tool, it can be automated via scripts.
**Azure Storage Explorer**: GUI tool for interacting with Azure Storage data. It is cross-platform, available for Windows, MacOS, and Linux. You can copy to and from containers, change storage tiers, create and manage storage containers, and generate (Shared Access Signature) SAS tokens to share file access permissions with others.
**Azure File Sync**: A service installed on an on-prem server that syncs local files with an Azure storage service.

### **Migration Options**

**Azure Migrate**: A service that helps migrate servers, databases, web apps, and more from on-prem or another cloud provider to Azure. It uses the Azure Migrate Appliance that runs on a dedicated Windows server / VM to discover on-prem resources and assess their readiness for migration to Azure. It can also help with the actual migration of resources to Azure.

**Azure Data Box**: A migration service suited for large amounts of data that would take too long to transfer over the internet, or in airgapped environments. When using Azure Data Box, Microsoft ships a physical device to the customer, which is filled with on-prem data and shipped back to Microsoft for upload to Azure. Data Box devices are ruggedized and designed to securely transport data between the customer and Azure. There are two current offerings for this service:

- **Data Box Disk**: Smaller, portable devices that can hold up to 7TB of data each. Encrypted with AES 128-bit encryption.
- **Data Box**: Larger, heavier devices that can hold up to 525TB of data. Encrypted with hardware based solutions and AES 256-bit encryption.
