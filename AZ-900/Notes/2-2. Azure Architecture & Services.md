# **AZ-900 Notes**

## **Azure Architecture & Services**

### **Azure Virtual Machines**
- Virtual environments that can be deployed and managed quickly and easily for compute, storage, servers, etc.
- Virtualize an entire computer: OS and Hardware
- Great for applications requiring complete control of the environment
- Common use cases include testing & development, cloud app hosting, disaster recovery, and "lift and shift" migration.
- Grouped into families so you can choose a size based on workload needs.
  
  <img width="853" height="200" alt="image" src="https://github.com/user-attachments/assets/94891652-19f7-4875-bb70-b789e0aea395" />

When provisioning VMs, you choose the size (CPU cores, RAM), storage disks, and networking (IP addresses, port config, etc.). With Azure VMs, at a fundamental level, you start by selecting a family that matches your workload behavior. Then, you choose the size based on performance needs and scale as needed.

**Virtual Machine Scale Sets** allow you to create and manage groups of identical, load-balanced VMs. This ensures you do not have to manually keep VM config consistent and micromanage utilization. You specify the OS and quantity of VMs in the scale set, and Azure will scale them using **Auto-scale** when necessary to keep up with demand. These VMs are also deployed using Availability Sets for fault tolerance.

**Virtual Machine Availability Sets** improve VM resiliency within a region and reduce the chance that all VMs are affected by maintenance or disaster. Availability Sets group VMs by **Update Domain**, which are VMs that can be rebooted together during planned maintenance, and **Fault Domain**, which are VMs that share a potential power or network failure point.

<img width="573" height="381" alt="image" src="https://github.com/user-attachments/assets/73faf5d3-8506-450e-9ece-9b09f2786ead" />

Using the image above as an example: Each physical rack is also a Fault Domain because the resources hosted on that rack all share a power, network, or other physical failure point. Each VM, regardless of the Fault Domain or Physical Rack it is located in, is assigned to an Update Domain that it would share with another resource it can be updated/rebooted/etc with. All of this is located in one Availability Set.

### **Azure Virtual Desktop**
- A desktop and application virtualization service offered in Azure.
- Allows users to securely and remotely access Windows desktop environments and apps from many different device types and locations, with the primary requirement being internet connection.
- Reduces IT support overhead and can be easily distributed or revoked from specific user groups as needed.

### **Azure Containers**
- A lightweight virtual environment that contains its own OS and can be created, scaled out, and stopped dynamically.
- Virtualize the OS -- no hardware virtualization means faster deployments, snapshots, etc.
- Great for applications requiring portability and speed

### **Azure Functions**
- Event-driven, serverless compute option that executes based on triggers and therefore alleviating the need to keep resources provisioned when there are no events

### **Azure Virtual Networking**
Virtual networks and subnets enable communication between Azure resources and users / on-prem computers. They provide capabilities like:
- Isolation and segmentation
- Traffic routing and filtering
- Connecting virtual networks, on prem resources, and Azure resources

**Public endpoints** have a public IP address and are accessible anywhere in the world. **Private endpoints** only have a private IP address and only exist within a virtual network.

##App Hosting Options##

### **Azure App Service**
PaaS service that can be used to create and host web apps in the cloud.

<img width="561" height="274" alt="image" src="https://github.com/user-attachments/assets/b087e960-358a-4ff0-94be-b9a6be644471" />

Each app service deployment has several front ends, which use a customized proxy-based routing module to send a request to a VM hosting the service being requested.\
These VMs run in an App Service Plan, which is a logical unit that helps with scaling web apps. All the VMs in an App Service Plan are identical and will run the same services.
